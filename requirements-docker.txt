# Runtime dependencies for the deployed container ONLY.
#
# This file used to be a byte-for-byte copy of requirements.txt -- the same 75 lines, which meant the
# production image shipped a whole notebook stack (ipython, ipykernel, jupyter_client, jupyter_core,
# debugpy, pyzmq, tornado, traitlets, jedi, parso, prompt-toolkit, stack-data, matplotlib-inline,
# nest-asyncio, comm, psutil) plus the scraper stack (beautifulsoup4, requests and their transitive
# deps) that only Backend/scripts/scrape_*.py needs. None of it is ever imported: after
# `import app; import main_test` and five full generations, the only module that arrives lazily is
# pandas. On Render's free tier the image is pulled on every cold start, so this is dead weight in
# the one place that actually hurts.
#
# HOW TO VERIFY a change here -- do not reason about it, build it:
#     docker build -t pfcc-test .
#     docker run --rm pfcc-test python -c "import sys; sys.path.insert(0,'/app/Backend'); import app"
#
# requirements.txt keeps the full set: CI installs it to run Backend/scripts/, which DOES use
# requests + beautifulsoup4 (the two scrape_*.py) and the dev tooling.
